# 게임 리그오브레전드의 루시안 딜량 계산기 (LoL Lucian Damage Calculator)

## 프로젝트 목적과 대상: 사용자
리그 오브 레전드 챔피언 '루시안'의 딜량을 레벨, 아이템, 룬, 상대 챔피언 조건에 따라 계산하고 시각화하는 웹 애플리케이션입니다. 실제 게임의 딜 계산 공식(방어력 감쇄, 치명타 확률/피해량, 스킬 쿨타임 등)을 기반으로, 빌드나 룬 선택에 따른 딜량 변화를 사전에 비교해보고 싶은 루시안 유저 또는 롤 딜량 계산 원리에 관심 있는 사람을 대상으로 합니다.

## 실행 방법
```bash
git clone https://github.com/hanjbin/lol---lucian---stats---dashboard.git
cd lol---lucian---stats---dashboard
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
streamlit run app/main.py
```
실행 후 브라우저에서 `http://localhost:8501` 접속. 테스트는 같은 환경에서 `pytest`로 실행합니다.

## 작업 과정 요약
1. Streamlit 기반 프로젝트 뼈대 구성 (폴더 구조, .gitignore, requirements.txt). 계산 로직과 화면 코드를 하나의 흐름으로 작성할 수 있고, 직접 이해하고 설명하기 쉬운 구조라서 Streamlit을 선택
2. 챔피언/아이템/룬 데이터 스키마 설계 및 예시 데이터 작성
3. 방어력 감쇄 공식(100/(100+방어력))을 적용한 기본 데미지 계산 로직 구현
4. 상대 챔피언 레벨을 아이템 개수 기준으로 자동 추정하는 기능 추가 (수동 조정 옵션 포함). 이후 도란 아이템과 신발은 개수에서 제외하도록 보완
5. 직접 고안한 스킬 콤보 계산 기능 추가 — 5초간 지속되는 상황을 위한 DPS 콤보(E-평-Q-평-W-평 후 스킬 쿨타임마다 평타 사이 스킬 삽입)와, 한 번에 몰아치는 폭딜 콤보(E-평-Q-평-W-평-R-평) 두 종류 구현
6. 치명타 계산을 기댓값(치명타 확률 기반 평균) 방식으로 반영, 무한의 대검 착용 시 치명타 피해량 보너스(+30%p) 및 루시안 궁극기의 치명타 확률 비례 발사 횟수 증가 반영
7. 실제 룬 페이지 구조(메인룬: 정밀/지배/마법/영감, 부룬: 정밀/지배/영감)를 재현하되, 원거리 딜러 실전 채용률이 높은 룬 위주로 목록을 선별해 범위를 관리 가능한 수준으로 제한
8. 도란의 검/활과 2티어 신발을 추가하고, 아이템 수치를 패치 16.19.1 기준으로 갱신. 크라켄, 주문검, 선체파괴자의 고유 효과를 계산에 반영
9. 단계마다 Claude Code로 기능 구현 → 로컬 환경에서 직접 실행/테스트 → 문제 발견 시 수정 요청 → 커밋, 순서로 반복 진행. GitHub 커밋 목록에서 Claude Code와 함께 작업한 기록을 확인할 수 있음

## 선별된 Claude Code 증거 및 검증 결과
- 단위 테스트 총 74개 작성, 전체 통과 확인 (`pytest` 실행 결과). 챔피언, 아이템, 아이템 효과, 룬, 룬 효과, 상대 챔피언, 스킬, 콤보, 데미지 계산을 파일별로 나눠 검증
- 방어력 감쇄 공식은 방어력이 음수인 엣지 케이스까지 포함해 테스트 (실제 롤에서도 방어력 디버프로 음수가 가능한 상황을 반영)
- Streamlit 앱을 로컬에서 직접 실행하여, 레벨/아이템/룬/상대 조건을 바꿔가며 계산 결과가 조건 변화에 맞게 달라지는지 수동으로 검증 (예: 아이템 개수를 늘렸을 때 데미지가 함께 증가하는지 확인)
- 경로 오류 사례: 웹앱을 처음 실행했을 때 `ModuleNotFoundError: No module named 'app'` 에러가 발생했다. 에러 메시지를 그대로 Claude Code에 전달하자, streamlit이 실행될 때 app 폴더만 경로에 올리고 프로젝트 최상위 폴더는 올리지 않는 것이 원인이라고 분석하고 수정했다. 재확인을 요청하자 서버를 따로 한 번 더 띄워 에러 없이 실행되는지 직접 검증했다
- 콤보 설계 사례: '단순히 데미지를 계산해줘'라고 요청하자 Claude Code가 4개 스킬의 조합 방식을 되물었다. 스킬을 누르는 간격, 스킬 가속과 공격 속도에 따라 시전 속도가 변하는 문제를 어떻게 처리할지 정해야 했고, 스킬 시전 시간과 투사체 이동 시간은 0으로 단순화했다. 복잡한 게임 로직은 정확한 조건과 순서를 직접 설계해 전달하는 방식으로 진행했다

## 효과적이었던 작업 방식 3가지
1. 작업을 단계별로 쪼개서 요청: 한 번에 전체 기능을 요청하기보다 작은 단위로 나눠 요청할 때, 의도에 더 정확히 맞는 결과와 높은 완성도를 얻을 수 있었다.
2. 추상적 표현을 구체적 수치로 변환: '세다', '빠르다' 같은 게임 관련 표현을 그대로 쓰지 않고, 실제 게임 수치를 조사해 구체화(치명타 배율, 레벨-아이템 매핑 기준 등)해서 요청했을 때 의도에 맞는 결과가 나왔다.
3. 질문은 창을 하나 더 띄워서 진행: 설명이 오래 걸릴 질문이 생겼을 때 작업 중이던 창에서 물으면, 나도 LLM도 지금 우선순위가 원래 작업인지 개념 설명인지 길을 잃었다. 원래 작업은 처음 창에서 계속하고 질문은 새 창에서 하자 작업 흐름이 끊기지 않았다.

## 겪은 어려움 3가지
1. LLM이 잘못 처리한 것을 내가 모르는 개념이라 알아차리지 못함: 뒤에서 문제로 이어지는 잘못된 처리도, 작업할 때는 내용을 이해하지 못해 지나치기 쉬웠다. 검증 과정을 추가하고, 어떤 작업을 했는지 쉽게 요약해 달라고 요청해 해결했다.
2. 말의 표현을 임의로 해석하거나 의도를 잘못 파악해 에이전트가 임의로 판단해 진행하는 경우가 잦았음: 구어적 표현 대신 의도를 명확하고 구체적으로 명시했을 때 이 문제가 해결됐다.
3. 인터넷상 데이터의 불확실성: LLM은 게임 프로그램을 직접 실행해 값을 확인하는 것이 아니라 인터넷에 공개된 정보를 찾아주는 것에 가까워서, 게임에 명시되지 않은 효과는 확인할 방법이 없었다. 대표적으로 스탯에 따라 캐릭터의 모션과 시전 속도가 달라지는 부분은 실험해 알아내기 어려워 시전 시간을 0으로 단순화했다. 무한의 대검이 궁극기 발사 수에 미치는 효과도 한 번 구현했다가 근거가 불확실해 커밋을 되돌리기(revert)로 제외했다.

## 알려진 한계점
- 상대 챔피언의 레벨은 실제 경기 데이터가 아니라, 아이템 개수 기준의 근사 매핑(가정값)으로 추정되며 실제 게임 진행과 다를 수 있다.
- 치명타는 실시간 난수(RNG) 시뮬레이션이 아닌 확률 기반 기댓값(평균)으로 계산되어, 실제 한 판의 결과와는 차이가 있을 수 있다.
- 무한의 대검이 궁극기 발사 수에 주는 영향은 정확한 수치를 확인하지 못해 반영하지 않았다.
- 아이템 수치는 패치 16.19.1 기준이라 이후 패치에서 달라질 수 있다.
- 룬은 전체 트리가 아닌 원거리 딜러 실전 채용률이 높은 일부만 구현되어 있다.
- 스킬 시전 시간, 투사체 이동 시간은 0으로 단순화되어 있다.
